# Days 15–16 — ReLU and a Two-Layer Forward Pass

**Status:** Both experiments completed

## Day 15 — Add ReLU to a Dense Layer

### Objective

On Day 14, I implemented a dense layer that calculated `Wx + b`. On Day 15, I added ReLU to each output. ReLU leaves positive values unchanged, replaces negative values with zero, and leaves zero unchanged.

```text
z = Wx + b
y = ReLU(z)
ReLU(z[i]) = max(0, z[i])
```

### Implementation

I kept the Day 14 experiment intact and used `experiments/day15_relu.cpp` for the new version. I reused the same weights and biases:

```text
W = [  1   2   3 ]    b = [ 0.5 ]
    [ -1   0   2 ]        [ 1.5 ]
```

For each row, I completed the dot product, added that row’s bias, and then applied ReLU once to the result. I kept the values before and after ReLU separate so I could verify each stage.

### Verification

| Input `x` | Before ReLU `z` | After ReLU `y` |
|---|---|---|
| `[2, 1, -1]` | `[1.5, -2.5]` | `[1.5, 0]` |
| `[0, 0, 0]` | `[0.5, 1.5]` | `[0.5, 1.5]` |
| `[-0.5, 0, 0]` | `[0, 2]` | `[0, 2]` |

The zero-input case and the exact-zero activation case test different things. With `[0, 0, 0]`, the biases make both values positive before ReLU. With `[-0.5, 0, 0]`, the first row’s dot product is `-0.5`, which cancels its `+0.5` bias. That gives ReLU an exact zero to test.

## Day 16 — Connect Two Dense Layers

### Objective

I used the Day 15 output as the input to a second dense layer. The first layer’s output, `h`, is the **hidden activation**. I applied ReLU only to the first layer so the final output could still be negative.

```text
h = ReLU(W1x + b1)
y = W2h + b2
```

### Implementation

I used `experiments/day16_forward_pass.cpp` and kept the Day 15 weights and biases for the first layer. The second layer uses weights `[2, -1]` and a bias of `0.25`.

| Stage | Input | Weight matrix | Output |
|---|---|---|---|
| First dense layer + ReLU | 3 elements | 2 × 3 | `h`, 2 elements |
| Second dense layer | 2 elements | 1 × 2 | `y`, 1 element |

The first layer produces two values, so the second layer needs two weights. Its single row produces a `1 × 1` result in matrix notation, which can be stored as a scalar in C++.

### Verification

| Input `x` | Hidden activation `h` | Second-layer calculation | Final output `y` |
|---|---|---|---:|
| `[2, 1, -1]` | `[1.5, 0]` | `2(1.5) - 1(0) + 0.25` | `3.25` |
| `[0, 0, 0]` | `[0.5, 1.5]` | `2(0.5) - 1(1.5) + 0.25` | `-0.25` |

The second case is a check on where ReLU is applied. If I accidentally applied it to the final output, `-0.25` would become `0`.

## Reproduction

From the repository root, compile and run each standalone experiment:

```bash
clang++ -std=c++20 -Wall -Wextra -Wpedantic \
    experiments/day15_relu.cpp -o day15-relu
./day15-relu

clang++ -std=c++20 -Wall -Wextra -Wpedantic \
    experiments/day16_forward_pass.cpp -o day16-forward-pass
./day16-forward-pass
```

If the input is hardcoded, change only `x` and recompile for each remaining case. Keep the weights and biases fixed. Compare the Day 15 values before and after ReLU, and the Day 16 hidden activation and final output, against the tables above.

## Reflection

Printing intermediate values made it easier to verify where each operation took effect. On Day 15, I could distinguish the biased sum from the activation. On Day 16, I could check what the first layer passed to the second instead of debugging from the final scalar alone. Together, the experiments gave me a small forward pass I can trace by hand before using an inference runtime.
